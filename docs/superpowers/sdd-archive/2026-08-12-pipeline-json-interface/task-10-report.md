# Task 10 report — `approve --review-file`

## What was built

**`pipeline/driver.py`** — two new functions inserted directly above `approve`:

- `_review_windows(windows)` — normalizes each submitted window down to the
  four geometry keys (`x`, `y`, `w`, `h`), rejecting non-object windows and
  non-numeric (or bool) field values with `BAD_INPUT`.
- `approve_review(stem, review) -> {"stem", "state": "approved", "fingerprint"}`
  — the single-snapshot approval path described in the brief.

**`pipeline/__main__.py`** — `approve` now mirrors the `preview` argument shape:
positional `stem` (`nargs="?"`) plus a `--stem` alias resolved by `_resolve`,
new `--review-file`, and the existing `--json`. Dispatch moved from an inline
lambda to `_approve_cmd` with `precheck=_approve_target`, so a missing or
doubled stem fails before the driver lock is taken. New `_read_review(path)`
helper parses the review JSON. `mutating=True` is unchanged.

**`tests/test_driver.py`** — the four tests from the brief plus two added for
gates the brief's tests did not exercise (see "Added coverage").

**`tests/test_cli.py`** — six tests for the new argument surface.

## Deviations from the brief, and why

1. **The brief's test crop windows were geometrically invalid — replaced.**
   `{"8x10": {"x": 0.075, "y": 0.0, "w": 0.85, "h": 1.0}}` on the seeded
   landscape 5784x4344 render is 4916x4344 px = aspect 1.132, against the 1.25
   an 8x10 landscape requires; `geometry.validate_crop` rejected it and the
   happy path failed with `BAD_INPUT`. Same for the 5x7 window. Replaced with
   values verified against the real `validate_crop` at the profile's 300 PPI:
   `8x10 = {"x": 0.05, "y": 0.0, "w": 0.9388, "h": 1.0}` and
   `5x7 = {"x": 0.0, "y": 0.04, "w": 1.0, "h": 0.951}`. Both are deliberately
   offset from `geometry.centered_crop_norm` (which would give x=0.0306 and
   y=0.0245), so the test still distinguishes "persisted what was submitted"
   from "recomputed a default" — it would not if the windows were generated by
   calling `centered_crop_norm` in the fixture.
   The dependent assertion `rec["crops"]["8x10"]["w"] == 0.85` became
   `rec["crops"] == review["crops"]`, which is strictly stronger.

2. **`_review_windows` normalizes once, before validation *and* persistence**
   (brief stripped `source` only for validation). Required by the gate: a
   `source` key surviving into `rec["crops"]` makes `recipe.fingerprint`'s
   `_check_crops` raise a bare `ValueError`, which escapes as an `INTERNAL`
   envelope rather than `BAD_INPUT` — and it would do so on a recipe already
   accepted, not at input time.

3. **Added `isinstance(audit, list)` to the audit check.** The brief's
   condition accepts a bare string: `all(isinstance(c, str) for c in "eyes")`
   is `True`, so `"eyes open"` would pass and persist as a list of single
   characters. The gate specifies "non-empty list of strings".

4. **Added three shape guards** in `_review_windows`: the `crops` container
   must be an object, each window must be an object, and each geometry field
   must be a non-bool number. Without the first two, `.items()` on a list or
   string raises `AttributeError` → `INTERNAL`; without the third, a bool that
   survives the geometry checks reaches `_check_crops` inside `fingerprint` →
   `INTERNAL`. (Note the container guard only fires for a *truthy* non-dict —
   `review.get("crops") or {}` already folds an empty list into `{}`, which
   then fails the missing-windows check.) None of the three changes what is
   persisted — the `rec` mutation is in-memory and nothing is written on these
   paths; all three convert the error code from `INTERNAL` to `BAD_INPUT`,
   which is what the gate requires.

5. **`_read_review` raises typed errors**: `BAD_INPUT` for malformed JSON or a
   non-object top level, `NOT_FOUND` for an unreadable/missing file. Left
   implicit in the brief; without it a malformed file yields an `INTERNAL`
   envelope from `json.JSONDecodeError`.

6. **No git commands run.** The brief's Step 5 includes `git add`/`git commit`;
   the team-lead's instruction to run no git commands takes precedence. Nothing
   is staged or committed — the working tree carries the change.

7. Gate run with the absolute interpreter path given by the team-lead rather
   than the brief's relative `.venv/bin/python`.

## Added coverage (beyond the brief's four tests)

- `test_approve_review_strips_echoed_source_tag` — submits windows carrying
  `source: "suggested"` (exactly what the `crops` command emits) and asserts the
  persisted recipe holds geometry only.
- `test_approve_review_rejects_invalid_window_without_persisting` — an

- `test_approve_review_requires_both_crops_and_audit` extended with the three

## Self-review against the stated correctness properties

Verified mechanically by walking the AST of `approve_review` and counting calls:

- **Single snapshot** — exactly `1x recipe.load`, `1x provenance.gather_material`,
  `1x provenance.review_revision`, `1x provenance.stale_styles`,
  `1x recipe.fingerprint`, `1x recipe.save`. `review_revision`, `stale_styles`,
  and `fingerprint` are each passed the same `rec` and the same `material`; no
  re-read exists between the gates and the persist.
- **Stale gates** — reached only when `expected_review_revision` is present and
  non-None; both raise before any mutation of `rec`, and the only writes in the
  function (`recipe.save`, `manifest.save`) sit after them.
  `test_approve_review_stale_revision_changes_nothing` and
  `..._requires_fresh_previews` cover both branches.
- **CLI path skips both gates** — the `if expected is not None:` block is the
  sole guard; `_read_review` never injects the key. This is what
  `test_approve_review_happy_path` proves: the seeded repo has no previews at
  all, so every style is stale, and the test would fail with `STALE_REVIEW` if
  the gates ran when `expected_review_revision` is absent.
- **Input gates** — audit and both-crops checks run before the snapshot, so a
  malformed request does not even read the recipe.
- **Validation failure persists nothing** — `_render_dims` and `validate_crop`
  failures raise before `rec["crops"]` is assigned; assignment is in-memory and
  `recipe.save` is only reached on success.
- **Legacy `approve` untouched** — extracted the current function body by AST
  span and diffed it against the pre-change text: byte-identical, zero diff
  lines. `_current_fingerprint` (its two-read path) is likewise untouched, and
  `approve_review` deliberately does not call it.
- **Manifest update matches legacy** — same three-call sequence
  (`manifest.load` → `set_state(..., "approved")` → `photos[stem]["fingerprint"]`
  → `manifest.save`) as `approve()`.

## Notes for the reviewer

- `approve_review` validates *every* submitted window, not only the two in
  `paths.CROPS`. An unrecognized crop name (e.g. `"4x6"`) raises `KeyError`
  inside `geometry.SIZES`, surfacing as `BAD_INPUT` — fail-closed, and only
  `paths.CROPS` entries are persisted. This follows the brief's loop shape; if
  the reviewer prefers an explicit "unknown crop" message, that is a one-line
  change.
- `_read_review` runs inside the dispatch lock, so an unreadable review file
  briefly contends for the driver mutex. Moving it into the precheck would mean
  either reading the file twice or threading the parsed body through
  `_dispatch`; left as-is deliberately.
